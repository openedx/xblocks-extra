Internationalization
####################

All user-facing text content should be marked for translation. Even if this application is only run in English, our
open source users may choose to use another language. Marking content for translation ensures our users have
this choice.

Follow the `internationalization coding guidelines`_ in the Open edX Developer's Guide when developing new features.

.. _internationalization coding guidelines: https://docs.openedx.org/en/latest/developers/references/developer_guide/internationalization/i18n.html

OEP-58 Integration
*******************

This project follows `OEP-58`_ for centralized translation management. Translations are managed through the
`openedx-translations`_ repository, which runs a daily GitHub Actions workflow that:

1. Clones this repository
2. Runs ``make extract_translations`` to extract translatable strings
3. Commits the combined source ``.po`` file
4. The Transifex GitHub App syncs the file to Transifex for the translation community

.. _OEP-58: https://docs.openedx.org/en/latest/developers/concepts/oep58.html
.. _openedx-translations: https://github.com/openedx/openedx-translations

Project Structure
*****************

Each XBlock in ``src/`` has its own locale configuration::

    src/
    ├── audio/
    │   ├── conf/
    │   │   └── locale/
    │   │       ├── config.yaml          # i18n-tools configuration
    │   │       └── en/LC_MESSAGES/
    │   │           └── text.po          # Per-xblock extracted strings
    │   └── .tx/
    │       └── config                   # Transifex resource mapping
    ├── feedback/
    │   ├── conf/locale/...
    │   └── .tx/config
    ├── imagemodal/...
    ├── qualtricssurvey/...
    ├── sql_grader/...
    └── submit_and_compare/...

    conf/                                # Repository root
    └── locale/
        └── en/LC_MESSAGES/
            └── django.po                # Combined file for OEP-58 pipeline

The combined ``conf/locale/en/LC_MESSAGES/django.po`` at the repository root is what the openedx-translations
pipeline uses. It is generated by merging all per-xblock ``text.po`` files using ``msgcat --use-first``.

Marking Translatable Strings
*****************************

Mark translatable strings in Python::

    from django.utils.translation import gettext as _

    # Translators: This comment will appear in the `.po` file.
    message = _("This will be marked.")

Mark translatable strings in JavaScript::

    // Translators: This comment will appear in the `.po` file.
    var message = gettext("Custom message.");

See the `edx-developer-guide <https://docs.openedx.org/en/latest/developers/references/developer_guide/internationalization/i18n.html>`__
for more information.

Make Targets
*************

..  list-table::
    :widths: 30 70
    :header-rows: 1

    * - Target
      - Description
    * - ``extract_translations``
      - Extract translatable strings from all XBlocks, merge JS strings into Python catalog,
        rename to ``text.po``, then combine all into ``conf/locale/en/LC_MESSAGES/django.po``
    * - ``compile_translations``
      - Compile ``.po`` files into ``.mo`` message files for each XBlock
    * - ``dummy_translations``
      - Generate dummy (Esperanto) ``.po`` files for visual testing
    * - ``build_dummy_translations``
      - Extract, generate dummy, and compile translations in one step
    * - ``validate_translations``
      - Build dummy translations and detect changed source files
    * - ``detect_changed_source_translations``
      - Check if source ``.po`` files are up-to-date
    * - ``pull_translations``
      - Pull translations from Transifex for each XBlock
    * - ``push_translations``
      - Extract and push source translation files to Transifex
    * - ``install_transifex_client``
      - Install the Transifex CLI client

Verifying Translations Locally
*******************************

Extract and compile::

    $ make extract_translations
    $ make compile_translations

Check the combined output::

    $ cat conf/locale/en/LC_MESSAGES/django.po

Build and test with dummy translations::

    $ make build_dummy_translations

Verify Transifex configuration (requires ``tx`` CLI)::

    $ cd src/<xblock_name> && tx status

Troubleshooting
***************

If there are any errors compiling ``.po`` files, run the following command to validate::

    $ make validate_translations

**Note:** The ``.gitignore`` ignores ``*.po`` and ``*.mo`` files. This is expected — translation source
files are managed in the `openedx-translations`_ repository, not committed here. The openedx-translations
workflow uses ``git add -f`` to force-add the files to its own repository.
